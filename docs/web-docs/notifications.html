Using it

Notifications

LightLMS keeps an in-app inbox for every person and can send the same message by email. Every person decides, per event and per channel, what they want.

The inbox

The bell in the header carries the number of unread messages, on every page. The count is shared with the page rather than fetched on its own, so the badge is right after any navigation.

A message can be marked as read, and the whole inbox can be marked as read at once. A notification links to the thing it is about, so one click lands on the hand-in or the grade.

The events

Event When it fires
submission.received A learner hands in an assignment.
submission.graded A teacher marks a hand-in.
quiz.attempted A learner submits a quiz attempt.
certificate.issued A certificate of completion is issued.
deadline.upcoming An assignment deadline is near.

Preferences

A person controls the preferences under Notifications → Preferences. The choice is per event and per channel, so somebody may keep the in-app message and switch the email off.

When no preference exists for a channel, the default of the event decides. A preference for one channel says nothing about the other.

Email

Email is sent through the queue, so a slow mail server never blocks a request. With MAIL_MAILER=log the messages are written to the log file instead of being sent, which is the right setting for a test installation.

A queue worker has to run for queued jobs to be processed at all. See Deployment.
